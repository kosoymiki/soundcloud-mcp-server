# Byte-level production audit — 2026-11-10

Scope: every tracked file (99 at audit start), every module, every directory of
`soundcloud-mcp-server` 2.1.0 → 2.2.0. Method: full read of the source (11 686
lines in `src/`), static analysis of error paths, and live probes (unit tests,
mock E2E, real HTTP server, real SoundCloud web session).

Severity scale:

| Level | Meaning |
|---|---|
| **P0** | Remote compromise, credential exfiltration, auth bypass with impact. |
| **P1** | Data corruption/duplication, crash, unbounded resource use, security control bypassable. |
| **P2** | Incorrect behaviour in a real edge case, information disclosure, resource leak. |
| **P3** | Robustness/observability gap with a workaround. |
| **P4** | Style, docs, cosmetic. |

## Result

- **P0: 0 found.** No path lets an unauthenticated remote party execute code,
  read SoundCloud credentials, or bypass authentication on a non-loopback bind.
- **P1: 10 found, 10 fixed.**
- **P2: 20 found, 20 fixed** (one documented as a deployment constraint: single
  server process per `DATA_DIR`).
- **P3/P4: listed with the fix applied where it was cheap and safe.**

## P1 findings (all fixed)

### P1-1 Non-idempotent retries could duplicate side effects
- **Where:** `src/soundcloud/http.ts:111-200` (pre-fix retry condition).
- **What:** `429` was retried for every method, including `POST /tracks`,
  `POST /comments`, likes/reposts/playlists.
- **Why:** a retry after the server already processed the request duplicates
  content (two tracks, two comments).
- **Fix:** retries are opt-in for non-GET methods; GET/HEAD retry by default.
  `retryable: true` remains available for known-idempotent calls.
- **Evidence:** `tests/hardening.test.ts` — POST 429 → 1 fetch, GET 429 → 3.

### P1-2 Ambiguous upload timeout could duplicate a track
- **Where:** `src/soundcloud/api.ts:159-172`, `382-430`.
- **What:** the upload body could be fully delivered, the response lost, and the
  retry loop uploaded the same file again.
- **Why:** `POST /tracks` is not idempotent; no server-side idempotency key.
- **Fix:** `isAmbiguousUploadFailure()` detects “body fully sent + TIMEOUT/
  NETWORK/5xx” and stops with an explicit “check the account before retrying”
  error. 401/429 still retry because they cannot have created a track.
- **Evidence:** unit test covers full/partial body and 401.

### P1-3 MCP session expiry leaked transports and servers
- **Where:** `src/mcp/sessions.ts:25-91` (pre-fix used `TtlMap`).
- **What:** `TtlMap.entries()` swept expired entries before `sweep()` saw them,
  so `delete()` never ran: SSE transports stayed open, `server.close()` was
  never called, and the `createdAt` side map grew forever.
- **Why:** two independent expiry mechanisms for the same data.
- **Fix:** a plain `Map` with one explicit `sweep()` that always goes through
  `delete()` (closes the transport) and evicts the oldest at the cap.
- **Evidence:** `tests/hardening.test.ts` — expired session → transport closed.

### P1-4 `/mcp-v2` buffered unlimited request bodies
- **Where:** `src/server.ts:39`, `285-305`.
- **What:** the route collected the whole body into memory before auth-independent
  parsing; `/mcp` had a 4 MB parser limit, `/mcp-v2` had none.
- **Why:** memory exhaustion from one authenticated client (or a leaked token).
- **Fix:** `MAX_MCP_BODY_BYTES = 4 MiB` checked from `Content-Length` and while
  streaming; 413 + connection close.
- **Evidence:** code path + live smoke (below).

### P1-5 Panel setup was CSRF/DNS-rebinding reachable; loopback origin was rejected
- **Where:** `src/panel/api.ts:51-66`, `300-320`.
- **What:** `POST /panel/setup` checked only the socket address. A page on the
  same host (or DNS rebinding) could overwrite the stored SoundCloud app
  credentials. Conversely, `PUBLIC_URL=http://localhost:PORT` rejected
  mutations made from `http://127.0.0.1:PORT`.
- **Fix:** origin allowlist includes public origin + localhost/127.0.0.1;
  setup additionally requires `Sec-Fetch-Site` same-origin/none; Host header is
  validated for panel/API/OAuth paths, not just `/mcp`.
- **Evidence:** `tests/hardening.test.ts` — foreign origin 403, loopback origin
  accepted.

### P1-6 Multipart upload could crash or hang the server
- **Where:** `src/panel/api.ts:75-185`.
- **What:** no `error` handler on the write stream, no `aborted` handler on the
  request: disk-full crashed the process (unhandled `error` event), a dropped
  client left the promise and the temp file forever.
- **Fix:** `failStream` + `req.once("aborted")`, single-settle guard, cleanup.
- **Evidence:** reviewed paths; `tests/panel-api.test.ts` still passes both
  success and oversize cases.

### P1-7 Bootstrap could drop the stored refresh token
- **Where:** `src/auth/store.ts:135-170`.
- **What:** `ensureLocalConnection({accessToken})` rebuilt the record without
  `scRefreshToken`, so the next expiry forced a full re-auth.
- **Fix:** missing fields inherit from the existing local connection.
- **Evidence:** `tests/hardening.test.ts`.

### P1-8 Orphan artwork temp file
- **Where:** `src/uploads/service.ts:221-246`.
- **What:** embedded artwork was written to `DATA_DIR` before checking that the
  created track had a URN; if not, the temp file was never deleted.
- **Fix:** resolve artwork only when `trackUrn` exists, delete in `finally`.
- **Evidence:** code path + unit tests for upload metadata unchanged.

### P1-9 MD5 of the upload read the whole file into RAM
- **Where:** `src/web/upload.ts:169-172`.
- **What:** the comment claimed slices; the code called `readFileSync` on a file
  that can be 4 GB.
- **Fix:** stream into the hash (`pipeline(createReadStream, hash)`).
- **Evidence:** `web.test.ts` ETag/MD5 assertions pass.

### P1-10 Presigned S3 PUT had no timeout
- **Where:** `src/web/upload.ts:182-200`.
- **What:** a stalled S3 connection held a session forever.
- **Fix:** `AbortSignal.timeout(30 min)`.

  high-entropy tokens, not exploitable) — left as is.
